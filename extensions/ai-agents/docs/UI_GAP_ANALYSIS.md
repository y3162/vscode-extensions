# UIギャップ分析

調査日: 2026-10-16。比較対象は 0.4.0 の Webview、ユーザー提供の Cursor IDE / Codex IDE 拡張 / ChatGPT デスクトップの画面、および `yutat23/cursor-agent-sidebar` v0.3.7（commit `63a1672`）のソース。

参考にした画面は次のとおり。

- Cursor IDE: セカンダリサイドバー上部の「New Agent」。入力カードの下段左にモードピル（Agent）、右にモデル名と Effort（Gemini 4 Argon High）、添付と音声。タイトルバーに新規・履歴・メニュー。
- Codex IDE 拡張: セカンダリサイドバー。上部に最近のチャット（タイトルと相対時刻、実行中のドット、View all）。下部に固定の入力カード。カード内に `+`、権限（Full access）、モデルと Effort。カードの下に `Work locally`。
- ChatGPT デスクトップ: 右寄せのユーザーメッセージ、吹き出しのない本文、広い段落間、完了した作業の1行要約（「11m 36s 作業しました」）、Composer 上のフルアクセス警告、入力カード内の権限とモデル。

これらの画面はリポジトリに含めない。個人のチャット内容が写っているため。

## 0.4.0 との差分

| 領域 | 0.4.0 | 参考UI | 0.5.0 で行うこと |
| --- | --- | --- | --- |
| 全体 | 設定セレクトとボタン列がチャットの上を占有する | チャットと入力欄が主役 | 常時表示はヘッダー1行、メッセージ、下部の Composer だけにする |
| ヘッダー操作 | Webview 内の新規・履歴・変更 | ネイティブのタイトルバー（+、履歴、…） | `view/title` のアイコンとオーバーフローメニューへ移す |
| エージェント選択 | 設定グリッドのセレクト | 製品ごとに1か所 | ヘッダーのドロップダウン1か所。タブにはしない |
| Composer | 独立した textarea と送信ボタン | 角丸カード。下段にモード・権限・モデル・送信 | カード化。高さは内容に合わせ、上限は 40vh |
| モデル | Quick Pick と詳細設定ボタン | 入力欄の「モデル名 + 薄い Effort」 | 表示だけカードへ移し、選択は既存の Quick Pick のまま |
| 権限 | サンドボックスと承認のセレクトを常時表示 | 1つの権限チップと、必要なときの警告 | チップとポップオーバー。危険な状態だけバナー |
| 作業場所 | フォルダセレクトを常時表示 | カード下の `Work locally` | カード下に Local・フォルダ・バックエンド |
| メッセージ | 全ロールが枠付きカード。プレーンテキストが多い | ユーザーは右寄せ、本文は地の文 | その区別。Markdown は見出し・リスト・表・コード |
| ツール | 先頭行だけの `details`。失敗と成功の区別が弱い | 要約1行、詳細は展開 | 種別・状態・対象。失敗は別色。連続実行はグループ |
| 長い作業 | 途中経過がすべて展開されたまま | 完了後は「作業しました」の1行 | 完了ターンは折りたたむ。実行中は開いたまま |
| 承認・質問 | Composer 直上の単一カード。質問は最初の1件だけ送る | 会話の流れの中 | 会話末尾のカード。複数質問はまとめて送る |
| 履歴 | ボタンを押すと小さな一覧 | チャット一覧がメッセージ領域を覆う | 同じ領域のパネル。空の画面には最近の数件 |
| 詳細設定 | メイン画面に全部ある | 普段は出さない | Webview 内のシートと、VS Code の設定画面 |
| テーマ | `--vscode-*` のみ。固定に近い余白 | OS のテーマに溶ける | 変数を維持し、ハイコントラストと reduced motion を足す |
| 更新 | 毎イベントで全文を再描画 | 追記中のブロックだけ更新 | メッセージは差分、描画はターン単位。下端にいるときだけ追従 |

## 採用しないもの

- 音声入力、他社ロゴ、クラウド実行の起動ボタン。
- 参考拡張の `innerHTML` 描画。エージェント出力は DOM と `textContent` のみ。
- 参考拡張で、失敗したツールが成功と同じ緑になる点。
- キーボード操作のないメニュー、`prefers-reduced-motion` を無視した無限アニメーション、px 固定でフォント設定を上書きする文字サイズ。
- プロバイダーをまたいだ「Full access」などの共通名への無理な統一。表示は各 Capabilities の実値に合わせる。

## 画面状態

| 状態 | メッセージ領域 | Composer |
| --- | --- | --- |
| 新しいチャット | 最近のチャットと短いヒント | 入力可能。モードは選択肢が2つ以上のときだけ |
| 既存チャット | ターン。完了分の作業ログは折りたたみ | 通常 |
| 実行中 | 現在のターンを開いたまま更新 | 送信はキュー。停止ボタンを表示 |
| 承認待ち | 末尾にカード。ヘッダーの点を警告色 | カードの操作を優先 |
| ツール実行中 | グループの要約が実行中になる | 実行中と同じ |
| エラー | 本文とは別のエラーブロック（再試行・ログ・診断） | 入力は続ける |
| 履歴 | メッセージ領域を一覧で覆う | 残す |
| 詳細設定 | メッセージ領域をシートで覆う | 残す |

## 共通にするものと、プロバイダーごとに変えるもの

共通: レイアウト、ターン、Composer の形、履歴、差分の開き方、Quick Pick のモデル選択。

プロバイダー固有: モードの有無（Codex SDK は Agent のみなのでピルを出さない）、権限チップの文言、承認カードを出せるか（Capabilities の `interactiveApproval`）、Steer、バックエンド名（SDK / ACP / App Server）。
