# UI Architecture

0.8.0 の画面構成。推論、サンドボックスの強制、ツール実行、モデル一覧の取得元は変えない。Composer から開くモデル設定を、Webview 内の階層メニューにした。

## 境界

```text
Webview (src/webview, dist/webview)
  Home と Chat のページ、描画、入力、ポップオーバー、詳細設定のシート
Extension host
  セッション、Capabilities、差分の表示と復元、Quick Pick、確認ダイアログ
SDK / ACP / App Server
  推論とツール
```

モデル名を押すと Webview が `loadModelCatalog` を送り、返ったカタログで Effort、対応している Context と Fast、モデル一覧を描く。選択は `setModel` と `setModelParam` でホストへ戻す。コマンドパレットの Quick Pick は残す。Cursor ACP はモデルをセッションへ送らないため、Composer のモデル名はメニューを開かない。

ページは Webview ごとに持つ。ホストの `ViewShell` には入れない。2つのサイドバーは同じ会話を共有したまま、別のページを開ける。

## 画面

```text
Home   Codex ▾              新規チャット  設定
       セッションカード（新しい順。実行中と承認待ちだけ印を付ける）

Chat   戻る     タイトル     設定
       メッセージだけがスクロール
       入力カード（モード、モデル、添付、送信。実行中は停止）
       Local · フォルダ · バックエンド
```

Home ではメッセージと入力欄を隠す。Chat ではセッション一覧を隠す。どちらも DOM は残す。戻る、同じセッションを開き直す、Webview を作り直す、のいずれもエージェントを止めない。実行中に別のセッションを選ぶと、Home に留まり、実行が終わるまで切り替わらない。

詳細設定は歯車から、今のページの上に開く。ログイン、APIキー、診断、使用量、ルール、ログ、バックエンド、サンドボックス、承認はここにある。ビュータイトルには同じボタンを出さない。コマンド登録は残す。

プロバイダーの選択は Home だけ。コントローラーは実行を1つしか持たない。切り替えると、これまでどおり新しい会話になる。

## Webview のモジュール

| ファイル | 役割 |
| --- | --- |
| `app.ts` | 起動、ページ、メッセージ、描画のスケジュール、下書きの保存 |
| `header.ts` | Home のプロバイダーと Chat の戻る、タイトル、設定 |
| `history.ts` | Home のセッションカード |
| `transcript.ts` | ターンの DOM、スクロール追従、「最新へ」 |
| `turns.ts` | メッセージ列をターンとセグメントへ分ける。DOM を持たない |
| `markdown.ts` | ブロック単位の描画。確定したブロックのノードは再利用する |
| `cards.ts` | 承認、計画、質問 |
| `composer.ts` | 入力、添付、モード、モデル、送信と停止、環境行 |
| `popover.ts` | キーボードで操作できるメニュー |
| `settings.ts` | メッセージ領域を覆う詳細設定 |
| `dom.ts` / `strings.ts` | 要素生成と日英の文言 |
| `styles.css` | `--vscode-*`、em、コンテナクエリ |

フレームワークは入れない。エントリは esbuild が `dist/webview/main.js` にまとめる。CSS と Codicon のフォントは同じディレクトリに置き、CSP の `style-src` と `font-src` は Webview のオリジンだけを許す。

## 通信

ホストから Webview へは `state` を送る。`shell` はヘッダーと Composer に必要な全体。`messages` は前回からの差分（削除、更新、並び）で、本文が変わっていないメッセージは再送しない。実行中は 16ms に1回へまとめる。実行が終わった更新はすぐ送る。Webview を開き直したときは全文を送る。

実行中のエージェントは Webview を破棄しても止めない。ページは `vscode.getState` の `page` で戻す。

Webview からホストへは、従来の `send` / `enqueue` / `configure` / `resolvePermission` / `resolvePlan` / `resolveQuestion` に加え、警告の非表示、追加ディレクトリの削除、相対パスの `openFile` を送る。承認・計画・質問には待ちごとに発行したトークンを付け、ホストは現在の待ちと一致しない回答を捨てる。`navigate` の `history` は Home、`chat` は Chat、`settings` は詳細設定である。

## 描画

- ユーザーは右寄せ。エージェントの本文は地の文。
- 連続したツールは1つのグループ。失敗は成功と違う表示にする。
- 完了したターンは、最後の本文以外を「作業しました」に畳む。実行中のターンは開いたまま。
- 下端から 60px 以内にいるときだけ新しい出力へ追従する。それ以外は位置を保ち、「最新へ」を出す。
- 追記中の Markdown は、未完了の最後のブロックだけを描き直す。
- セッションカードはタイトルだけ。長い名前は省略し、ツールチップに全文を残す。

## セキュリティ

- エージェント出力を HTML として解釈しない。外部リンクは http と https だけ。ローカルパスと `file://` はファイルボタンからホストへ渡し、ワークスペース内のファイルをエディターで開く。
- ファイルを開くパスは、ワークスペース内か、そのターンが報告した変更に限る。
- `turn.diff` や `patch` のような実体のないパスは、件数とパッチの表示だけ行い、復元や Diff Editor には渡さない。
- 自動承認をオンにする確認ダイアログは、これまでどおりホストが出す。

## 参考実装から取らなかった実装

`cursor-agent-sidebar` のレイアウト（スクロールはメッセージだけ、Composer はカード、ポップオーバーは入力の近く、ツールは要約、下端への追従）は採用した。ソースの移植はしていない。`innerHTML`、失敗ツールの緑表示、操作できないメニュー、質問を Quick Pick に出す処理は採用していない。
