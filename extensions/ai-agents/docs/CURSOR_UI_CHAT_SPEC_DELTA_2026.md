# 実チャットと前回仕様の差分（2026-10-29）

前回仕様は [CURSOR_UI_IMPLEMENTATION_SPEC_2026.md](CURSOR_UI_IMPLEMENTATION_SPEC_2026.md) の改訂前である。実測は通常ワークベンチのチャット列（幅 400px、Dark、1280×800）である。空の Agents Window の 608px ホームとは別画面なので、そちらの数値は消ししていない。

優先度は、実装時に見た目が変わるものからである。

## 推奨する仕様変更

1. Composer の操作行を 40px から 28px にする。根拠は会話表示中の `.composer-bar-input-buttons`。優先度は高い。
2. Composer の枠を前景 20% にする。ユーザーカードの 12% とは別に測れた。優先度は高い。
3. 活動見出しを 14px、行高 22px にする。12px はレビュー帯のラベルに残す。優先度は高い。
4. レビュー帯に、未受け入れの Undo と Keep を足し、受け入れ後は件数と Review だけにする。優先度は中。
5. ユーザーカードの文字を、バンドルどおりの 14px 固定から、エディタの文字サイズに戻す。実測は 13px / 18.2px。優先度は中。
6. 640px 中央寄せ、空思考を出さない規則、回答の枠なし、レビューを Composer 直上に置くことは維持する。

## 採らないもの

- ユーザーカードの半透明背景。Glass の合成であり、Webview では `input-background` のままにする。独自判断。
- Build の `rgb(241, 180, 103)`。Dark の実測だが、Light と High Contrast を見ていない。独自判断。
- 計画ドキュメントの 800px エディタ。Webview はターン内に Markdown を開く。独自判断。
- Context Usage パネル。実測したが、表示するデータがプロトコルに無い。
- Plan の質問ツールバー。この拡張の操作には無い。
- チャット列を 400px に固定すること。分割エディタの結果であり、サイドバーの幅規則ではない。
